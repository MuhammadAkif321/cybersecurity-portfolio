# Key Terms and Definitions — Module 2

These definitions are written in simple language for revision.

| Term | Simple definition |
|---|---|
| **Asset** | Anything valuable to an organization that it needs to protect, such as data, computers, software, or buildings. |
| **Attack vector** | A path or method an attacker uses to reach a target or break through security defenses. |
| **Authentication** | The process of checking that someone is who they claim to be. Example: signing in with a password or fingerprint. |
| **Authorization** | Deciding what an authenticated user is allowed to access or do. |
| **Availability** | Making sure information and services are accessible to authorized users when they need them. |
| **Biometrics** | Physical or behavioral characteristics used to help verify identity, such as fingerprints or facial recognition. |
| **Confidentiality** | Ensuring that information is seen only by people who are authorized to access it. |
| **CIA triad** | A security model based on confidentiality, integrity, and availability. It helps organizations think about protecting information and systems. |
| **Detect** | A NIST CSF function focused on finding and analyzing possible cybersecurity events. |
| **Encryption** | Converting readable data into an encoded form so that it cannot be understood without the appropriate key. |
| **Govern** | A NIST CSF function focused on setting and overseeing cybersecurity strategy, policies, responsibilities, and risk-management expectations. |
| **Identify** | A NIST CSF function focused on understanding an organization's assets, systems, risks, and cybersecurity needs. |
| **Integrity** | Keeping information accurate, complete, and trustworthy, and protecting it from unauthorized changes. |
| **NIST Cybersecurity Framework (CSF)** | A framework from the National Institute of Standards and Technology that helps organizations manage cybersecurity risk. |
| **NIST Special Publication 800-53** | A NIST publication containing a catalog of security and privacy controls for information systems and organizations. |
| **OWASP (Open Worldwide Application Security Project)** | A nonprofit organization and community that works to improve the security of software and web applications. |
| **Protect** | A NIST CSF function focused on putting safeguards in place to reduce cybersecurity risks. |
| **Recover** | A NIST CSF function focused on restoring systems, services, and operations after a cybersecurity incident. |
| **Respond** | A NIST CSF function focused on taking action during and after an incident, including containing it and managing its impact. |
| **Risk** | The possibility that a threat will cause harm to an asset, including harm to its confidentiality, integrity, or availability. |
| **Security audit** | A review of an organization's security controls, policies, and procedures against defined expectations. |
| **Security controls** | Safeguards used to reduce risks and protect an organization's assets and information. |
| **Security framework** | A set of guidelines, standards, and best practices that helps an organization manage cybersecurity. |
| **Security posture** | An organization's overall ability to protect its assets and data, manage risks, and respond to changes or incidents. |
| **Threat** | A circumstance or event that could cause harm to an asset or organization. |

## Important distinctions

### Authentication vs. authorization
- **Authentication:** Who are you?
- **Authorization:** What are you allowed to access or do?

### Confidentiality vs. integrity vs. availability
- **Confidentiality:** Keep information private from unauthorized people.
- **Integrity:** Keep information accurate and protected from unauthorized changes.
- **Availability:** Keep information and services accessible to authorized users.

### NIST CSF functions
Remember the six functions: **Govern, Identify, Protect, Detect, Respond, Recover**.

### Risk vs. threat
- A **threat** is something that could cause harm.
- **Risk** considers the possibility and impact of that harm to an asset.

*Note: NIST CSF 2.0 uses six functions, including Govern. These notes use the current six-function structure introduced in the module glossary.*
